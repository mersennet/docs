Complete reference for JSON-RPC methods supported by Mersennet. All examples use `https://rpc.mersennet.com` as the RPC URL.

Mersennet implements the standard `eth_` namespace plus native extensions across `net_`, `web3_`, `txpool_`, `mersennet_`, `mersennet_orders_`, and `mersennet_bridge_`. The privacy/ZK methods (shielded transfers, SP1 state proofs, selective-disclosure reads) also live in the `mersennet_` namespace and are documented separately in the [Shielded JSON-RPC reference](/developers/privacy/shielded-rpc).

---

## Standard Ethereum Methods

### eth_blockNumber

Returns the current block number.

**Parameters:** None

```bash
curl -X POST https://rpc.mersennet.com \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}'
```

**Response:**

```json
{ "jsonrpc": "2.0", "id": 1, "result": "0x1234" }
```

## MersennetOrders CLOB Methods

The native order book engine accessible via RPC. The CLOB precompile is at address `0x0000000000000000000000000000000000000100`.

**Orders route through consensus.** State-mutating CLOB calls (`submitOrder`, `cancelOrder`, `depositCollateral`) do not mutate state synchronously — they build a precompile transaction, submit it to the mempool, and return `{ accepted, txHash }`. The order takes effect when the transaction mines (~1-2 blocks, a few seconds). Poll `mersennet_orders_getOpenOrders` or subscribe to the `MersennetOrdersTrades` WebSocket topic to observe the result.

You can also call the precompile directly with a **wallet-signed transaction** (MetaMask, ethers.js) — see [Deployed Contracts](/resources/contracts/) for the Solidity interface. On this testnet the unsigned RPC path is enabled for frictionless demos (`mersennet_orders.allow_unsigned_orders_rpc = true`); on mainnet it will be disabled and signed precompile transactions become the only write path.

### mersennet_orders_addMarket (disabled)

Markets are seeded deterministically from the genesis configuration on every node. This method is disabled: adding a market over RPC would mutate only the node that received the call, forking the CLOB state across the network. Calling it returns a `-32601` error explaining this. The same applies to `mersennet_orders_setMarginParams` and `mersennet_orders_liquidate`.

---

### mersennet_orders_submitOrder

Submit a limit order to the CLOB. The order is packaged as a `placeOrder` precompile transaction and mined through consensus.

**Parameters:**

1. `orderObject`:
   - `owner`: Trader address
   - `market_id`: Market ID (integer)
   - `side`: `"buy"` or `"sell"`
   - `price`: Limit price (hex)
   - `size`: Order size (hex)
   - `tif`: Time-in-force: `"gtc"` (Good-Til-Cancel), `"ioc"` (Immediate-or-Cancel), `"fok"` (Fill-or-Kill)

```bash
curl -X POST https://rpc.mersennet.com \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"mersennet_orders_submitOrder","params":[{"owner":"0x7f5ce38fb2553e95dd8ef9182a80bc219c9a0d45","market_id":1,"side":"buy","price":"0xfde8","size":"0x64","tif":"gtc"}],"id":1}'
```

**Response:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "accepted": true,
    "txHash": "0xc180addcc72d1655a210238bd8d6f21dae84df21d1e6175c4f56b643ed530ca1"
  }
}
```

The order rests (or fills) once `txHash` mines. Fills are emitted as `trade` domain events in the block and on the `MersennetOrdersTrades` WebSocket topic.

If the order crosses existing resting orders, `trades` will contain fill details and `filled` will be non-zero.

## Precompiles

Mersennet exposes native functionality through EVM precompiles, callable from Solidity via `eth_call` or transactions:

| Address | Name | Purpose |
|---------|------|---------|
| `0x…0100` | MersennetOrders CLOB | On-chain order book: place/cancel orders, collateral, positions, best bid/ask |
| `0x…0200` | Shielded Transfer | Private note-to-note transfer (`shieldedTransfer(bytes)`) |
| `0x…0201` | Shield / Unshield | Transparent ⇄ shielded bridge (`shield`, `unshield`) |
| `0x…0202` | Code Publication | Register/revoke a contract code attestation |
| `0x…0300` | State-Proof Verifier | Verify an SP1 state-transition proof on-chain (`verifyStateProof(bytes)`) |

(Addresses are the 20-byte form, e.g. `0x0000000000000000000000000000000000000100`.)

:::note
The shielded precompiles (`0x0200`, `0x0201`, `0x0300`) and shielded RPC methods activate with the privacy hard fork. The transparent MersennetOrders precompile is disabled after privacy activation in favor of the shielded order path.
:::
