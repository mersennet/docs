The public WebSocket endpoint `wss://rpc.mersennet.com` is enabled for `eth_subscribe` subscriptions (`newHeads`, `logs`, `newPendingTransactions`) — send regular JSON-RPC calls over HTTPS. Nodes you run yourself serve WebSocket subscriptions on port 8546.
:::

## Protocol upgrades

Consensus rules change at announced block heights ("switches" in the node config), written into the canonical node config. Every node must run a release that implements the rule before the height; the staking page and `mersennet-check` warn when yours is behind. Heights come from `mersennet_validatorSet` (`params`) and `mersennet_orders_getProtocol` (`switches`); ETAs assume ~2.1 s blocks.

| Height | When (UTC) | What changes | Minimum release |
|---|---|---|---|
| 1,440,000 | Wed 2026-09-16 15:45 UTC (active) | Block rewards credited to the operator wallet; compact (base64) gossip encoding | `9e3a508` (15 Sep) |
| 1,569,600 | Sat 2026-09-19 19:23 UTC (active) | **Benching**: 3 missed leader slots → out of the leader rotation until the epoch boundary. **Escalating jail**: consecutive jails last 1, 2, 4, 8, 16, 24 epochs. **Agent delegation** on the CLOB precompile (`setAgent` / `revokeAgent`; one-click trading in the terminal). **Finer ticks**: MRSN, SOL and ARB switch to `priceScale` 100 — on-chain prices become human × 100 and the markets trade on $0.01 ticks; books, positions and last prices are rescaled in place | `f67d812` (18 Sep; the 17 Sep build also carries it) |
| 1,605,600 | Sun 2026-09-20 ~16:30 (live estimate on the [upgrades page](https://explorer.mersennet.com/upgrades)) | **Settlement**: one collateral unit = one MRSN (existing balances ÷10¹⁸ once), realized PnL settles into collateral at every fill, 10% initial / 5% maintenance margin with keeper liquidations (`liquidate(address)`, 1% fee split keeper/insurance fund), self-trade prevention. **Contracts act as themselves on the CLOB and staking precompiles**: the precompiles authorise on the call frame's `msg.sender` instead of the transaction origin. A contract that calls `depositCollateral` / `placeOrder` / `setAgent` now owns its own account (the maker vault depends on this, and its deposits open at this height), and a contract can no longer act on the account of the user calling it. Direct transactions are unchanged | `f67d812` (18 Sep) — `settlement_height`, `frame_caller_height` |
| 1,969,200 | Tue 2026-09-29 16:40 UTC (active) | **Refused order-book and staking calls revert with their reason** (`Error(string)`, shown by wallets and the terminal) and charge ~20k gas instead of the whole gas limit. **Fee floor and split**: the base fee never falls below 1 gwei (it still rises with usage); of the base fee each block collects, 50% goes to the protocol treasury (`0xacAC…7777`), 25% to the block proposer and 25% is burned. A transaction priced under the floor is refused — [how fees work](/architecture/tokenomics/#transaction-fees) | `9be4f83` (26 Sep) — `revert_reasons_height`, `fee_floor_height` |
| 2,127,600 | Sat 2026-10-03 ~15:30 UTC (live estimate on the [upgrades page](https://explorer.mersennet.com/upgrades)) | **Up to 50 validators**: the active set grows from 12 to 50 at this epoch boundary; still ranked by self-stake + delegations if more register | 30 Sep release — `max_validators_height` |

ETAs assume the observed block time (~2.1 s: missed leader slots stretch the nominal 2 s) and drift by tens of minutes over a day — the live countdown is on the explorer's [Protocol upgrades](https://explorer.mersennet.com/upgrades) page and the terminal's [staking page](https://trade.mersennet.com/staking), or `GET https://trade.mersennet.com/api/v1/protocol/switches`. The same explorer page keeps the record of **completed** upgrades: the block's actual timestamp next to the estimate that was on record and the difference between them (`GET /api/v1/protocol/upgrades`).

Current release: [mersennet.com/downloads/latest.json](https://mersennet.com/downloads/latest.json) (`build_sha`). Upgrading is the [install command](/validators/run-a-node/#step-2--install-one-command) again.

## Add Mersennet to MetaMask

import AddToMetaMask from '../../../components/AddToMetaMask.astro';

<AddToMetaMask />

Or run this code in your browser console (with MetaMask installed):

```javascript
await window.ethereum.request({
  method: 'wallet_addEthereumChain',
  params: [{
    chainId: '0x1FFFF', // 131071 in hex
    chainName: 'Mersennet Testnet',
    nativeCurrency: {
      name: 'MRSN',
      symbol: 'MRSN',
      decimals: 18
    },
    rpcUrls: ['https://rpc.mersennet.com'],
    blockExplorerUrls: ['https://explorer.mersennet.com']
  }]
});
```

:::note
Chain ID `131071` in decimal equals `0x1FFFF` in hexadecimal. Both Mersennet chain IDs are Mersenne primes: testnet is `131071` (2¹⁷−1) and mainnet will be `8191` (2¹³−1).
:::

### Usage Notes

- **MersennetOrders**: The native on-chain order book — powers [trade.mersennet.com](https://trade.mersennet.com).

- **MockUSDC, MockUSDT, MockDAI**: Test stablecoins with a public `faucet()` mint.
